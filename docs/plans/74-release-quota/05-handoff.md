# Implementation Handoff

## Change Tier And Smallest Complete Outcome

Bounded distribution reliability enhancement with in-pattern terminal errors.
Ship request reduction, safe quota advice, typed/human receipt fidelity, tests
and documentation together. No new architecture/platform mechanism.

## Dependency Order And Reviewable Slices

1. Fail count and exact-byte tests; add private inspection result and bounded
   staging/full-verifier reuse. Exit: budgets and all trust/race regressions pass.
2. Fail refusal/header tests; add bounded typed quota advice and API propagation.
   Exit: ordinary refusal/cancel/unavailable distinct, no unsafe output/retry.
3. Fail menu/receipt tests; render in existing patterns and record real native
   synthetic matrix. Exit: explicit recovery and unchanged ownership proven.
4. Full CI, exact-head self-review, reconciliation and durable docs promotion.

## Acceptance Traceability

Counts/original bytes/trust -> slice 1 distribution fixtures. Quota/failure
classification -> slice 2 transport/API fixtures. Effects/UX/explicit recovery
-> slices 2–3 API/menu/native evidence. Detailed matrix in `04-verification.md`.
All slices must pass full required checks before reviewed implementation merge.

## Documentation Promotion

Promote measured counts, trust boundaries and quota recovery to existing
`docs/development.md` distribution section and appropriate user-facing README
release guidance; typed error contract to existing API documentation. Retain
exact-head evidence under `docs/evidence/distribution/`. Record approved
discovery provenance and decision/measurement references in reconciliation;
remove temporary plan and retire discovery pack only after its useful evidence
has a durable destination. Do not create one permanent document per plan stage.

## Pull Request And Review Contract

Planning branch `design/74-release-quota`; implementation `feature/release-quota`.
Draft implementation has a top-level `Refs #74`, exact-head engineering review
under ADR 0003, required CI, red/green evidence, native evidence manifest and
plan-to-implementation reconciliation. Promote actual behavior into docs and
remove this temporary plan before marking ready. Keep #74 open for later
candidate acceptance/release; discovery approval is not implementation approval.

## Explicit Non-Goals And YAGNI Boundary

No credentials, cross-command cache, conditional-request assumptions, automatic
retries, generic download broker, bootstrap rewrite, signet changes, native
plugin updates or production activation. No new public verified-state input.

## Exceptions That Reopen Design

Return for design if fresh identity checking requires additional trusted state,
the count target needs weakened source checks, headers require body disclosure,
or a new credential/persistence/irreversible boundary becomes necessary. Minor
private helper naming is not a product rescope; record implementation drift.
