# Implementation Handoff

## Change Tier And Smallest Complete Outcome

Additive public administration behavior and a substantive terminal journey. Ship
declarations, assessment, menu/CLI parity and optional prompt coherently; a table
or renamed existing inspector alone does not satisfy the issue.

## Dependency Order And Reviewable Slices

1. Finalize product/solution design and exact-head review. Resolve explicit
   selection, data limits and metadata-only reader seams first.
2. TDD declarations, identities and pure classification.
3. TDD bounded static observations and API/CLI response contracts.
4. TDD menu rendering, navigation and sanitized prompt generation.
5. Verify explicit native-check handoff separately in disposable fixtures.
6. Capture exact-head rendered evidence, reconcile, promote docs and remove
   temporary plans/discovery before leaving implementation draft.

## Acceptance Traceability

Declarations/evidence criteria map to slice 2; safe missing/malformed/unknown
observations to slice 3; menu/agent parity and prompt to slice 4; deeper native
boundary to slice 5. Slice 6 verifies the complete interaction and current head.
Detailed tests live in [verification](04-verification.md).

## Documentation Promotion

- New-machine workflow and exact side effects: `docs/setup.md`, `docs/runbook.md`.
- Shared API/CLI and schema bounds: `docs/interface.md`.
- Metadata ownership and evidence distinction: `docs/architecture.md`.
- Actual engineering/terminal results: scoped `docs/evidence/` record.
- Toolchain/testing and unsupported cases: `docs/development.md` as needed.

Delete this six-file plan and `docs/discovery/15-machine-readiness` after durable
promotion during implementation reconciliation. Git and PRs retain provenance.
Do not duplicate temporary stages as separate permanent manuals.

## Pull Request And Review Contract

Planning branch `design/85-machine-readiness`; later implementation branch
`feature/machine-readiness` from the reviewed basis. Record exact-head ADR 0003
self-review, current required CI, meaningful native evidence and reconciliation.
Only selected engineering authority applies; retain independent candidate gates.

## Explicit Non-Goals And YAGNI Boundary

No automatic install, native settings rewrite, authentication, credential copying,
signet read/write, synchronization, agent launch, telemetry, universal registry,
package management or private capability adaptation. No expanded memory catalog.

## Exceptions That Reopen Design

New execution/private-data authority, inferred compatibility, native behavior
contradicting the no-execution boundary, inaccessible truthful evidence matching,
or work beyond implementation require revisiting design. Ordinary implementation
refinements must remain recorded without becoming artificial blockers.
