# Verification And Release Design

## Red/green sequence

1. Engine selection fixtures: two scopes, current/superseded/conflicting heads,
   unrelated records/sources/devices, exact journals and historical foundlings.
   Prove selected-only default, explicit opt-ins, missing-ID errors and no clock
   conflict resolution. Compare source tree bytes/metadata before and after.
2. Preview/strict plan tests: no bodies, counts/IDs/digests/categories, deterministic
   output, no writes, source/binding drift, invalid/oversized selections and plans.
3. Omission tests: place distinct synthetic secret-like markers in every exported
   string surface, including IDs/scopes, labels, classifications, timestamps,
   reasons, origin citations, author/session/model and extension values. Prove
   effective dependency closure and no hidden original identifiers/digests.
   Omitting all categories leaves only fixed structure/counts/ordinals/notices.
4. Apply tests: exact reconstructed plan, existing/symlink/ancestor/case aliases,
   bank/binding/state/foundling overlaps, stale source or parent identity,
   exclusive private files, denied read-only, cancellation and injected partial
   writes. Source invariance includes ignored state and no Git activity.
5. Compiled CLI typed/wrapper parity with synthetic binding and report; execute
   in the designated terminal lab without using personal memory. Inspect output
   as JSON data, not executable instructions. Verify projected reports cannot
   open as signets. No network/credential dependency.

## Acceptance and rollout

No new rendered menu: machine-readable CLI contract and readable JSON artifact,
with exact-byte/schema/semantic verification. Full pinned host and hosted CI,
privacy review and exact-head engineering self-review precede merge. Existing
recall/sync/native regressions must remain green. Record any runtime limits and
unverified native platforms. Candidate acceptance/release is a separate gate.

## Recovery and production preflight

No migration, destructive cleanup or live-bank action. Partial artifact paths
remain inspectable; no automatic retry/removal. Production readiness preflight
is not applicable to this implementation-only plan. Testing and source merge do
not authorize export of the owner's memory or public release.
