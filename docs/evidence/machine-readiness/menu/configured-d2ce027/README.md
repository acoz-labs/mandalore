## Effects and limits

Before each journey, a complete 136-entry fixture inventory captured paths,
bytes, modes, mtimes and directories across signet, binding, native profiles,
owned state, wrappers, malformed input and dependency fixtures. Static assessment
and prompt viewing left every entry unchanged in all five cases. Native checks
were evaluated separately: Codex changed only the temporary `tmp/arg0` directory
metadata, Pi only its profile-directory metadata. Bank, binding, package, runtime
and registration bytes remained unchanged. The PATH-local Node execution trap
was never invoked; native Pi used its installed pinned Node runtime through the
explicit launcher. Its static presence was not represented as a version check.

Terminal flags/control characters were restored on every exit, excluding only
Darwin's transient PENDIN bit as documented in the parent checkpoint. Normal
journeys exited zero; the deliberately failed native check exited one. No
screen-reader, other-locale/font or non-host native-platform claim is made.

These actual source-bound runs complete the adverse-state engineering checkpoint,
not final implementation-head verification or product acceptance. The earlier
missing/default-No/arrows/Vim/EOF/Ctrl+C checkpoint remains separately identified.
Final-head reconciliation and its source-bound matrix must precede PR readiness.
