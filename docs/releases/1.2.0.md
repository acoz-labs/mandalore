# Mandalore 1.2.0

[v1.2.0](https://github.com/acoz-labs/mandalore/releases/tag/v1.2.0) was published
September 21, 2026 from the independently accepted retained artifact. All eight
public assets matched the accepted candidate. No product rebuild, personal
installation update or live memory migration occurred at publication.

## Included changes

- Scoped, reviewable exports with explicit history/journal selection and derived
  redaction. Preview and apply are pinned; original memory is preserved.
- Deliberate withdrawal and restoration of selected records, with bounded
  discovery of withheld history and exact-head checks.
- Metadata-only retention previews under an explicit policy, without automatic
  expiry or deletion.
- Safer Codex connection updates: replacement is deferred without stopped-session
  acknowledgment, with actionable restart and partial-state notices.
- Complete recovery commands in narrow/plain/TUI output, preserving literal shell
  meaning and default-No/Back behavior.

## Compatibility and upgrade

Format 1 remains supported and is the default. Installing the CLI does not migrate
a signet. Withdrawal requires a separate explicit format 2 upgrade with stopped
writers and per-clone opt-in. Older clients refuse upgraded banks; an offline
clone that has not received the new state may retain old content.

Withdrawal is not erasure: journals, historical references, Git history, external
copies and already-returned model context may remain. Correction does not
implicitly restore a withdrawn record. Retention preview performs no destructive
apply or automatic expiry.

The 1.1 updater safely refuses the new supported-format declaration. Use the
[review-before-running bootstrap](../../README.md#install), or download the 1.2
platform executable and SHA256SUMS from the same release and verify the checksum
before execution. Run the verified executable's
`release install --version 1.2.0 --prefix DIR` and review the installation plan.
Never edit the immutable manifest to bypass compatibility checks. These checks
trust the official release, not an independent signing authority.

CLI installation and native connection replacement are separate. Exit all
affected Codex sessions before replacing the connection, then start fresh
sessions. Pausing between turns is not equivalent to exiting. Pi also needs a
fresh session after a connection update.

Keep verified owned older runtimes for explicit recovery. A binary rollback does
not downgrade a bank and must not be used to make an older reader open format 2.
Follow the [runbook](../runbook.md) for reviewed backup/recovery procedures.

## Native evidence and limits

[macOS ARM64 model journeys](https://github.com/acoz-labs/mandalore/issues/124#issuecomment-5763293917)
used Codex 0.155.0 and Pi 0.85.1: ordinary recall, withdrawal, fresh-session
absence and explicit restoration of the latest superseding revision. The live
Codex update journey verified old-session continuation after deferral,
stopped-session activation and fresh-session recall. An extra native plugin
inventory probe timed out; that unsuccessful attempt remains disclosed alongside
the completed journey.

[Linux ARM64 acceptance](https://github.com/acoz-labs/mandalore/issues/124#issuecomment-5763118461)
used retained binaries and actual CLI/plugin/MCP components in a Linux
VM/container. It did not run Linux model conversations or establish bare-metal,
unprivileged or universal filesystem behavior. AMD64 assets are cross-built,
not equivalent native acceptance.

[Recovery rendering](https://github.com/acoz-labs/mandalore/issues/77#issuecomment-5763257901)
used an exact-source synthetic test renderer; retained production
installation/rollback was checked separately. No universal terminal, clipboard,
screen-reader, hot-reload or model-reliability claim is made.
