# Mandalore 2.5.0

Release 2.5.0 makes the Claude plugin's prompt hook more selective. It finds
a short question inside filler, and it injects less on prompts no memory
answers. Of two decisions on one subject, the newer now ranks first. This is
a server release; the Claude plugin stays at 2.3.0 and doesn't change.

There is no signet format change, no state file change and no configuration
change. 2.5.0 adds no public HTTP or OAuth path, so the Cloudflare path
allowlist needs no change, and it needs no new secret.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

All of it is in `memory_context`, which the hook calls, except the newer-first
ranking, which `memory_recall` has too
([#232](https://github.com/acoz-labs/mandalore/issues/232); see
[retrieval](../retrieval.md#250-filler-collisions-generic-words-and-newer-decisions)).

- **Filler around a short question.** The hook judges each of the prompt's
  first 3 question clauses as well as the whole prompt. "Before we start,
  remind me: Which editor do I use? One line is fine." now finds the editor
  preference. Records rank by their best relevance over the prompt and its
  clauses, not by recall order alone. "okay", "right", "fine", "please" and
  "check" no longer count as topic words.
- **Generic words.** A two-word prompt whose only match with a record is a
  common word in its body, such as "number" or "week", no longer injects that
  record ("Is 17 a prime number?"). The words are a fixed list of 50 nouns for
  time, quantity and kinds of thing.
- **Lone summary words.** A record matching one of the prompt's words, in its
  summary, is no longer injected when another of the prompt's words is in no
  record at all ("How do I install Redis on Ubuntu?"). A name the prompt
  capitalizes still counts.
- **Names the signet lacks.** When a prompt names something no record holds
  ("in Rust?", "on a GitHub account"), a record is injected only if one of
  the prompt's words is in its summary or identifiers, not just its body.
- **Newer decisions.** Two decisions (or two preferences) in one scope are on
  one subject when their summaries are nearly the same and their bodies
  overlap. Recall puts the newer directly ahead of the older, and the hook
  never injects the older without the newer. Neither supersedes the other:
  both stay current. A record revised for any reason, even a typo, counts as
  newer from that revision.
- **Unchanged.** The default budget stays 2048 bytes, and the top 3 records
  always appear. `memory_context`'s input and output, session de-duplication
  and every other tool are as before.

- **Sealed batch, 6 of 36 against a bar of 3**

  The coverage-path name collisions left, unchanged from 2.4.0, are
  [#262](https://github.com/acoz-labs/mandalore/issues/262).

Two question shapes lose their answer, both from the rules for names the
signet lacks:

- a question that names something no record holds and matches its answer
  only on one summary word, such as "Which shell do I use on my MacBook?";
- an "X or Y?" question whose X is only in the answer's body and whose Y is
  a name no record holds, such as "Helix or Neovim?" when only the editor
  preference's body says Helix. It depends on the order: "X or Y?", "X vs
  Y", "Should I use X or Y?" and "Do we use X or Y for this?" get nothing,
  while "Y or X?", "X?" and "What about X?" still get the answer. 2.4.0
  answers all 8 "X or Y?" questions of this shape in the evaluation set;
  2.5.0 answers none.

When X is in several records' summaries, a two-name "X or Y?" or "X vs Y"
injects X's records as "Y or X?" does: the first word of a prompt that is
nothing but names is exempt from the lone-summary-word rule
([evidence](../evidence/2.5/either-or.md)). It still anchors nothing. So a
prompt of three names ("Beacon or Cortana or Siri?"), or one whose answer
rests on a name's anchor, can still differ from its reverse. The replay figures are in the
[hook replay evidence](../evidence/2.5/hook-bytes.md).

## Upgrading

Upgrade the server as [2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server)
describe, using 2.5.0 in place of 2.1.0. Nothing is written differently, so
servers and clones that sync the same signet can upgrade in any order. The
plugin needs nothing: its hook already sends the prompt and session.

Some prompts that got memory on 2.4.0 get none on 2.5.0, by design. If a
question you rely on stops getting its answer, `memory_recall` still finds
it, and the [retrieval guide](../retrieval.md#evaluation-set) lists the
known limits.

## Recovery

Previous artifact: [2.4.0](2.4.0.md). Rolling back changes no data: 2.5.0
persists nothing new. The hook's per-session memory is in the server process,
so a rollback, like any restart, forgets which records each session was
given, and a record may be injected once more.

## Known issues

- The generic-word rule covers only the 50 words on its list. A two-word
  prompt that shares any other everyday word with a record's body can still
  inject it, as on 2.4.0.
- [#262](https://github.com/acoz-labs/mandalore/issues/262): prompts no memory
  answers can still inject through the coverage path when they share several
  words with a record's summary.
- [#264](https://github.com/acoz-labs/mandalore/issues/264): an all-lowercase either-or prompt loses its
  known first name. With three records whose summaries name Kopia and none
  naming Borg, "kopia or borg?", "borg or kopia?" and "kopia vs borg" each
  inject 3 records on 2.4.0 and none on 2.5.0, while the capitalized forms
  inject 3 on both (the reviewer's counts on the published binaries).
- The open issues listed in [2.4.0](2.4.0.md#known-issues).
