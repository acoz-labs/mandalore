# Mandalore 2.5.1

Release 2.5.1 gives a lowercase either-or prompt, such as "kopia or borg?",
the memory its capitalised form gets. 2.5.0 injected nothing for it. This is
a server release; the Claude plugin stays at 2.3.0 and doesn't change.

There is no signet format change, no state file change and no configuration
change. 2.5.1 adds no public HTTP or OAuth path, so the Cloudflare path
allowlist needs no change, and it needs no new secret.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

All of it is in `memory_context`, which the hook calls. `memory_recall`
doesn't change ([#264](https://github.com/acoz-labs/mandalore/issues/264);
see [retrieval](../retrieval.md#251-lowercase-either-or-prompts)).

- **Lowercase either-or prompts.** A bare either-or prompt is two or more
  words joined by `or` or `vs`, in any case, such as "kopia or borg?",
  "borg vs kopia" or "kopia or Borg?". With three records whose summaries
  name Kopia and none naming Borg, each such prompt now injects the 3 Kopia
  records, as "Kopia or Borg?" does. On 2.5.0 they got nothing. A bare
  either-or inside a question clause counts too: "In one line: kopia or
  borg?".
- **It only adds.** When 2.5.0 injects anything for such a prompt, the
  same lines come out, unchanged and in the same order, and any added
  records follow, whole, in the room left. When 2.5.0 injects nothing, the
  added records are packed as usual. The records added are ones that match
  the prompt in their summary or identifiers, each with the newer decision
  on its subject when there is one; the two are added together or not at
  all, so an older decision never comes without the one that replaces it. Capitalised forms are judged exactly as
  on 2.5.0. Within a session, a record the hook has already given is left
  out of later prompts, as before, and that includes added records.
- **Prompts no memory answers.** This includes prompts no record answers. A
  lowercase either-or that shares a word with a record's summary now gets
  that record, as its capitalised form already did on 2.5.0. With a "Coffee
  order" record, "tea or coffee?" injects it (2.5.0: nothing; "Tea or
  Coffee?" injects it on both).
- **Cost.** Such a prompt is judged twice, once as 2.5.0 does and once with
  the change. That adds about 2 to 6 ms at the median on the synthetic
  benchmarks, far inside the hook's 3 s timeout. Other prompts are judged
  once.

## Upgrading

Upgrade the server as [2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server)
describe, using 2.5.1 in place of 2.1.0. Nothing is written differently, so
servers and clones that sync the same signet can upgrade in any order. The
plugin needs nothing.

## Recovery

Previous artifact: [2.5.0](2.5.0.md). Rolling back changes no data: 2.5.1
persists nothing new. A rollback, like any restart, forgets which records
each session was given, and a record may be injected once more.

## Known issues

- `vs.` with a dot isn't covered: "Kopia vs. Borg" and "kopia vs. borg"
  inject nothing, as on 2.5.0, because the word after `vs.` starts a
  sentence. Write "vs" or "or".
- A wrapper without a `?` clause ("quick one, kopia vs borg"), "versus", and
  words of two letters or common words ("go or rust?", "this or that?") keep
  2.5.0's behaviour.
- Three names can still differ by order, in any case: "Beacon or Cortana or
  Siri?" gets nothing while "Siri or Cortana or Beacon?" gets the Beacon
  record, and "beacon or cortana or siri?" gets nothing, as on 2.5.0.
- The capitalised "X or Y?" limit from 2.5.0 stands: when X is only in a
  record's body and Y is a name no record holds, "X or Y?" gets nothing. The
  lowercase "x or y?" keeps its answer, on 2.5.0 and 2.5.1.
- The open issues listed in [2.5.0](2.5.0.md#known-issues), except #264.
