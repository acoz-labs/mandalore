# Razor Crest in Mandalore 1.5.0

Release closeout pending under [#146](https://github.com/acoz-labs/mandalore/issues/146).

Razor Crest connects authorized ordinary cloud chats to a persistent signet
replica through Streamable HTTP MCP. Local coding agents keep their own replicas;
delivered knowledge is shared through the same signet. The remote service adds
no arbitrary file, shell or installation tools. Isolated HTTP acceptance used
MCP protocol version `2025-03-26`; provider negotiation was not independently
captured. Remote saves require stable
request IDs and report local durability separately from Git delivery.

## Authentication and operations

The live deployment retains owner-only Access policy, restricted OAuth redirects,
private-origin header protection, no published service host port, and a guarded
fixed signet. The reference configuration uses five-minute OAuth access tokens
and a 24-hour refresh grant. These settings are configuration, not a claim of
observing every provider token-lifecycle boundary.

Exact-runtime synthetic-issuer tests rejected another signed subject, expired
and forged assertions, and unauthorized writes. Live origin tests rejected
missing/wrong secrets, missing/forged identity, an untrusted browser origin and
wrong host without memory disclosure. Removing the service subject grant and
restarting denied the existing connector; restoring the grant restored access.
The restart/readiness observation was approximately two seconds. Cloudflare
policy edits and in-flight requests are different boundaries; instantaneous
provider-policy revocation is not claimed.

A temporary metadata-only observer recorded a successful authenticated request
with an origin assertion whose issuance-to-expiry interval was approximately
24 hours. Only request time, issuance/expiry and response status
were retained; no token or memory body was logged. The observer was removed and
the direct route restored. This demonstrates that the origin assertion lifetime
must not be inferred from the five-minute OAuth setting. A successful request
after that observed expiry, with a renewed assertion, remains unverified. No
provider refresh-token exchange or 24-hour grant expiry is claimed.

## Durability and recovery

Exact-runtime isolated acceptance covered acknowledged undelivered saves and
discarded responses followed by SIGKILL, restart and identical request-key replay.
Record and revision IDs remained stable; changed payloads under the same key
were rejected. Restarted delivery completed. Concurrent corrections from two
independent replicas preserved conflicting heads and provenance. Withdrawals
remained hidden. Canon allowlists, subjects, independent snapshots, explicit
refresh, source withdrawal and restart invalidation passed; the full 24-hour
canon session lifetime was not waited out.

A consistent encrypted full-volume backup restored into a replacement container.
An authenticated identical request returned the original record/revision IDs
and successful delivery. The original service was restored afterward. Complete
replica/configuration backups and prior images are retained for recovery; a Git
clone alone cannot restore pending writes or local idempotency receipts.

The real signet installation uses a dedicated writer and repository-scoped Git
credential. Live remote reads, a semantic journal save, Git delivery and restart
health were verified. An encrypted full-state/configuration backup is retained.
The existing client URL and owner authentication were preserved. Installation
identifiers, data, credentials and raw evidence remain outside this repository.

## Limitations and maintenance

Configured validation passed at the exact release source, alongside the separate
[native integration acceptance](1.5.0.md#verification-and-scope). Interrupted and
failed fixture attempts are retained separately from successful observations.
The deployment uses existing host, domain and ingress resources; no new paid
service was provisioned. Account billing access was unavailable to the operator,
so this is not a blanket free-tier eligibility or future-pricing guarantee.

Retain the complete service volume, binding, credential references and image
identity. Review native and remote delivery receipts separately. Client labels
may retain an earlier test name when an existing authorized connector is reused;
the server's guarded signet identity determines the actual target.
