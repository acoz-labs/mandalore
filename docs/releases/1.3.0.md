# Mandalore 1.3.0

[v1.3.0](https://github.com/acoz-labs/mandalore/releases/tag/v1.3.0) was published
September 22, 2026 from the independently accepted retained artifact. All eight
public assets matched. Public fresh installation, update and retained rollback
passed without changing synthetic memory. Publication did not activate personal
connections or migrate a live signet.

## Included changes

- Native Claude Code integration with the shared MCP engine, memory skills,
  guided setup, inspection and repair.
- Enabled Claude Code, Codex and Pi sessions attempt bounded synchronization
  before foreground memory context and after semantic writes.
- Pending delivery retries at the next foreground opportunity. Local durability,
  delivery and semantic conflicts remain distinct; retrying delivery does not
  require saving the same record again.
- Shared coordination serializes transport. Orphan subprocesses cannot keep
  synchronization and memory-writer locks held after their parent exits.
- Successful and partial visibility receipts describe the actual session
  delivery attempt while preserving event identity and durability uncertainty.

## Enablement and compatibility

A reviewed connection plan that explicitly enables session transport authorizes
synchronization. Toggling a legacy plugin alone does not adopt that policy.
Requests not to remember or journal particular content still control
new semantic saves; existing saved records may synchronize. Conversational
no-sync is not a control for enabled sessions. Disable the complete integration
and start a fresh session to stop hooks, tools, skills and memory context.
Disabling cannot remove context already loaded.

Existing read-only connections retain enforced permissions. Administrative
local-only APIs retain their semantics. Updating the CLI does not automatically
replace native connections, change authentication or migrate memory. Review the
connection plan, exit affected sessions before replacement, then start fresh.
Independent native memory remains enabled and separate.

Formats 1 and 2 remain supported. Withdrawal/restoration still require separate
explicit format 2 enrollment; installation does not perform it. A runtime rollback
does not downgrade a bank or make an incompatible reader safe. Retain verified
owned runtimes and follow the [recovery runbook](../runbook.md).

## Native evidence and limits

Actual macOS ARM64 journeys used Claude Code 2.1.278, Codex 0.155.1 and Pi 0.85.1.
They exercised primitive save/delivery, stale and already-open destinations,
same-record corrections, manual compaction/resume, native interruption/retry,
content controls, disabled sessions and native-memory coexistence. Withdrawal
kept a retained native note from recreating shared knowledge; explicit restoration
reused the original record and content revision with truthful delivery receipts.

Claude reports the latest recorded value, but can question externally authored
corrections. After several rapid revisions its trust degraded and it requested
confirmation before treating the value as settled. The complete answers are
preserved in the native evidence. Acceptance proves bounded transport and current
recorded-value recall, not unconditional model agreement or seamless adoption
of every external revision. Memory is evidence, not authority or verification of
live implementation.

Pi manual compaction used a small synthetic retention setting; it was not default
large-context pressure. Codex startup/turn hook measurements were 414/225/593 ms
with 2,781/3,393/3,393 context bytes over local test transport, not an internet
latency guarantee. Disabled sessions were checked through inventories, prompt
absence and unchanged bank bytes; no independent network syscall trace is claimed.

Linux ARM64 exercised the retained CLI, MCP and adapters in an isolated pinned
container, without Linux model conversations. AMD64 artifacts are cross-built
and hashed, not native runtime acceptance. No daemon delivers work while all
harnesses are closed, and unsaved model output is not promised durable.
