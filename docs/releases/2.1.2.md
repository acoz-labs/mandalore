# Mandalore 2.1.2

[Release 2.1.2](https://github.com/acoz-labs/mandalore/releases/tag/v2.1.2)
makes `memory_remember` say which input to fix. A summary, body or reason over
its limit, and other input refused before anything is written, now return
`input.invalid` with `write_may_have_occurred` false, instead of a
`save.incomplete` that invited retrying input that could never succeed.

**The Claude plugin stays at 2.1.1, on purpose.** Nothing in it changes: its
guidance names neither the limits nor the error codes, and the limits reach
Claude through the server's tool schema. A 2.1.2 server beside a 2.1.1 plugin
is not a missed bump, and merging this change rolls nothing out to installed
plugins ([#229](https://github.com/acoz-labs/mandalore/issues/229)).

2.1.2 changes no OAuth state version, no signet format, no state file and no
configuration, and adds no public HTTP or OAuth path.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

- **Input errors are `input.invalid`**
  ([#243](https://github.com/acoz-labs/mandalore/issues/243)). The message
  names the field, its limit in UTF-8 bytes and the size received, for
  example `summary is 363 bytes; the limit is 256 UTF-8 bytes`, and never
  repeats the input text. The same applies to a blank `basis`, an unknown
  `kind`, `sensitivity`, `volatility` or `confidence`, a bad scope, a
  `record_id` without `supersedes` or the reverse, more than 32 `supersedes`,
  a correction that doesn't fit the record's history, and
  `memory_journal_append`'s kind and summary limits. Nothing is stored, so a
  retry with the same `request_id` and corrected input saves.
- **Stale corrections are `memory.stale_heads`.** On a format 2 signet, a
  correction whose `supersedes` aren't the record's current heads returns the
  code the visibility tools already use, again with nothing written. The
  [save errors](../server.md#tools) table lists each correction case by
  format.
- **The tool schemas state the limits.** `memory_remember`'s summary, body and
  reason, and `memory_journal_append`'s kind and summary, carry `minLength` 1
  and `maxLength` set to the byte limit. `maxLength` counts characters, and
  the descriptions say that non-ASCII text can be refused below it.
- **The CLI** (`mandalore memory remember`) gives the same field messages,
  still with exit code 2 for `input.invalid`. A stale correction on a format 2
  signet now returns `memory.stale_heads`, so its exit code changes from 2
  (2.1.1's generic `input.invalid`) to 1.

`save.incomplete` is unchanged, with the same message and fields, for every
failure that can follow a write. The error envelope keeps its shape, and
`memory_remember` already returned `input.invalid` for malformed arguments, so
existing clients need no change.

## Upgrading

Upgrade the server as [2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server)
describe, using 2.1.2 in place of 2.1.0. No signet or state changes, and
nothing on the client needs to change.

## Recovery

Previous artifact: [2.1.1](2.1.1.md). Rolling the server back to 2.1.1 changes
no data: records saved by 2.1.2 read the same. Clients then see
`save.incomplete` again for over-limit input.
