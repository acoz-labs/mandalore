Preparation issue #124 integrates #77, #112, #80 and #81. The published release
remains [1.1.0](1.1.0.md). A version change is neither artifact nomination nor
acceptance, publication or installation. Candidate coordinates and test receipts
must be recorded after the corresponding operations actually succeed.

## Compatibility and safe installation

Format1 remains supported and default for new banks. Runtime installation alone
does not change a signet. Withdrawal requires a separately reviewed format2
preview/apply with stopped writers, exact source/binding/checkpoint pins and
per-clone opt-in. Old evidence, signet identity and Git history survive. Refer to
the [runbook](../runbook.md) for explicit recovery, not automatic downgrade.

The published1.1.0 updater rejects the new supported-formats declaration. This
is a safe refusal, not permission to edit immutable release manifests. Use the
verified new platform executable to plan/apply installation, or the new reviewed
bootstrap after it is actually published. Verify checksums and source identity.
Native connection updates require the existing stopped-session acknowledgement;
do not infer supported hot reload from a surviving MCP process.

Shared protocol and distribution manifest schema remain version1. Source package
manifests remain development placeholders; the existing builder stamps VERSION
into runtime and both packages. The inventory stays eight files: four platform
executables, Codex ZIP, installer, manifest and checksums; Pi remains embedded.

Withdrawal is not erasure. Explicit history, independent journals, external
references, Git history, offline clones and already-returned model context can
retain content. Corrections do not restore withheld records. Concurrent restores
or unreviewed concurrent corrections remain withheld until explicit resolution.
Retention only previews selected metadata under an explicit policy: no TTL,
automatic withdrawal, destructive apply or semantic duplicate blacklist.

## Retain and nominate

After reviewed main passes required checks, build once with **Build retained
candidate**. Record source, run/attempt, artifact ID, archive digest and expiry.
Independently verify provenance and all eight assets, then nominate the same
artifact with the existing guarded workflow. Verify receipts for #77, #112, #80,
#81 and #124; the preparation PR must explicitly reference that issue set.

No earlier candidate acceptance can be transferred to new bytes. Expired or
defective artifacts need a new candidate and nomination. Do not rebuild accepted
payloads. See [retained candidate operations](../development.md#retained-actions-candidates).

## Exact-candidate verification matrix

Use the designated native lab, synthetic banks, local bare remotes and disposable
installation profiles. Preserve native authentication in place; never copy it or
personal memory into evidence. Confirm source/manifest/binary/Codex/Pi identities
before execution. Capture fixture inventories for no-effects claims.

1. **Recovery (#77):** repeat32/80-column plain/TUI/no-color output, default-No
   and Back. Verify emitted logical command bytes and exact arguments with inert
   shell handlers, including apostrophes, double spaces, Unicode and metacharacters.
   Retain actual rendered evidence; do not exhaust live quota or claim every
   terminal clipboard behaves identically.
2. **Update safety (#112):** exercise deferred and explicitly stopped-session
   native update paths, old/new connections, actionable restart/partial notices
   and preservation of unrelated state/auth/memory. Repeat the issue's native
   scenario rather than relying solely on fake adapters.
3. **Export (#80):** scoped current preview/apply, all redaction groups and
   dependencies, explicit history/journals, stale source/binding and destination
   refusal, cancellation/partial output and full source invariance. Verify report
   hashes/modes, no overwrite, no implicit checkpoint/delivery and no claim that
   derived output is a restorable bank or automatically safe to publish.
4. **Withdrawal (#81):** format1 unchanged; reviewed activation and interrupted
   recovery; released-reader refusal; per-clone opt-in and independent receipts;
   concurrent correction/withdrawal/restoration; current/history exports and
   independent journals/foundlings; bounded metadata-only retention. Fresh Codex
   and Pi sessions must discover explicitly requested withheld history without
   file scanning and restore latest reviewed content with exact heads. Ordinary
   recall must not use withheld evidence as current guidance.
5. **Distribution (#124):** verify all payloads/version stamping, safe old-updater
   refusal and verified-new-executable installation preserving the old owned
   runtime and unrelated files. Assert the format1 bank and binding do not change.
   Public bootstrap download is only verifiable after actual publication.

Record exact sources/artifact hashes, native versions, actual outcomes, faults and
limitations in a retained acceptance packet. Earlier-head recordings, component
tests, cross-builds and model runs are different evidence. Native Linux, other
models/locales/terminals and accessibility are unproven unless separately tested.

Synthetic quota/partial-receipt rendering uses the existing test-only native
driver compiled from the exact candidate source; that injection seam is absent
from release executables. Label those captures source-bound renderer evidence,
not execution of retained product bytes. Exercise real install/update behavior
with the verified retained executable separately; neither result substitutes
for the other or proves every possible production failure path.

## Acceptance, publication and closeout

An authorized human must review the exact nominated artifact, evidence and each
issue's original criteria and supply an actual verdict. ADR0002's historical
candidate-specific owner exceptions do not cover1.2.0. Resolve any required
acceptance authority explicitly; do not change the policy or manufacture a verdict
to make a workflow pass. Engineering self-review remains separate.

After acceptance, obtain publication authority and promote the same immutable
bytes through existing guards. Verify public assets and the issue delivery ledger,
then update release documentation and follow the
[product-page closeout](../product-page-closeout.md) contract. Keep release issues
open until their delivery gates complete. Personal installation or signet upgrade
requires separate authority even after publication.

Only after the approved recovery/memory-control batch is complete should #15/#14
be reassessed. Deterministic lifecycle synchronization is not added here; existing
automatic learning and agent-selected save-and-sync remain unchanged.
