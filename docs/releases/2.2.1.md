# Mandalore 2.2.1

[Release 2.2.1](https://github.com/acoz-labs/mandalore/releases/tag/v2.2.1)
rebuilds Mandalore with Go 1.26.11, which fixes GO-2026-6859: an HTTP/1
server crash on a `net/http` `MaxBytesReader` header race. `mandalore serve`
is the public HTTP endpoint and reaches that code, so a request that triggers
the race could take a 2.2.0 server down. Upgrade every server.

**The Claude plugin stays at 2.2.0, on purpose.** Nothing in it changes. A
2.2.1 server beside a 2.2.0 plugin is not a missed bump, and merging this
change rolls nothing out to installed plugins
([#229](https://github.com/acoz-labs/mandalore/issues/229)).

2.2.1 changes no behaviour, no OAuth state version, no signet format, no
state file and no configuration, and adds no public HTTP or OAuth path, so the
Cloudflare path allowlist needs no change.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

- **Go 1.26.11** ([#253](https://github.com/acoz-labs/mandalore/issues/253)).
  Every toolchain pin moves from 1.26.10 to 1.26.11: the mise config, the
  `go.mod` toolchain line (the `go` directive stays 1.26.0), the `bin/`
  guards, the release builder and candidate manifest checks, the workflows'
  setup-go, and both `golang:` base images. The manifest's `go_version` is
  `go1.26.11`. No module changes. `govulncheck` reports no reachable
  advisory.

## Upgrading

Upgrade the server as [2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server)
describe, using 2.2.1 in place of 2.1.0. No signet or state changes, and
nothing on the client needs to change. A server is protected only once it
runs the 2.2.1 binary.

## Recovery

Previous artifact: [2.2.0](2.2.0.md). Rolling back changes no data, and
brings back GO-2026-6859.
