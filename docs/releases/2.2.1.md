# Mandalore 2.2.1

[Release 2.2.1](https://github.com/acoz-labs/mandalore/releases/tag/v2.2.1)
rebuilds Mandalore with Go 1.26.11, which fixes GO-2026-6859: an HTTP/1
server crash on a `net/http` `MaxBytesReader` header race. `mandalore serve`
is the public HTTP endpoint and reaches that code, so a request that triggers
the race could take a 2.2.0 server down. Upgrade every server.

**The Claude plugin stays at 2.2.0, on purpose.** Nothing in it changes. A
2.2.1 server beside a 2.2.0 plugin is not a missed bump, and merging this
change rolls nothing out to installed plugins
([#229](https://github.com/acoz-labs/mandalore/issues/229)).

2.2.1 changes no behaviour, no OAuth state version, no signet format, no
state file and no configuration, and adds no public HTTP or OAuth path, so the
Cloudflare path allowlist needs no change.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

- **Go 1.26.11** ([#253](https://github.com/acoz-labs/mandalore/issues/253)).
  Every toolchain pin moves from 1.26.10 to 1.26.11: the mise config, the
  `go.mod` toolchain line (the `go` directive stays 1.26.0), the `bin/`
  guards, the release builder and candidate manifest checks, the workflows'
  setup-go, and both `golang:` base images. The manifest's `go_version` is
  `go1.26.11`. No module changes. `govulncheck` reports no reachable
  advisory.

## Upgrading

Upgrade the server as [2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server)
describe, using 2.2.1 in place of 2.1.0. No signet or state changes, and
nothing on the client needs to change. A server is protected only once it
runs the 2.2.1 binary.

## Recovery

Previous artifact: [2.2.0](2.2.0.md). Rolling back changes no data, and
brings back GO-2026-6859.

## Evidence and scope

The independent maintainer
[approved](https://github.com/acoz-labs/mandalore/pull/254#pullrequestreview-5859874193)
[#254](https://github.com/acoz-labs/mandalore/pull/254) in round 1, with no
findings, at exactly `838803b`
([pre-merge receipt](https://github.com/acoz-labs/mandalore/pull/254#issuecomment-6797773715)),
then [nominated](https://github.com/acoz-labs/mandalore/issues/253#issuecomment-6797873346)
and [accepted](https://github.com/acoz-labs/mandalore/issues/253#issuecomment-6797882479)
([receipt](https://github.com/acoz-labs/mandalore/issues/253#issuecomment-6797984312))
the retained candidate
`mandalore:95bbf17cfa8455b22a1dc01583e4638f5a92010e:sha256:a1a348eee1dde5e69235e39782d29be362f7a42adc5e8603605a9184e10cd0ee`,
built from `95bbf17`, the merge of #254. `bin/sdlc audit --before 8da6b65
--sha 95bbf17` passed. Acceptance used synthetic state only, with a temporary
`HOME` and `CLAUDE_CONFIG_DIR`; the old side was the published,
checksum-verified 2.2.0.

- **Issue criteria (#253):** the manifest's `go_version` is `go1.26.11`, and
  the darwin/arm64 binary reports `go1.26.11`. `go run
  golang.org/x/vuln/cmd/govulncheck@v1.9.0 ./...` at `95bbf17` reports no
  reachable vulnerability; its only unreached finding is GO-2026-5932,
  known and accepted. `govulncheck -mode=binary` is clean for all four
  binaries. The same binary scan of the published 2.2.0 reports
  GO-2026-6859.
- **Retained distribution:** `bin/build-artifacts` at `95bbf17`, in a clean
  worktree, gave the seven files for 2.2.1, and `SHA256SUMS` verifies them.
  `install.sh` is byte-identical to 2.2.0's, and the darwin/arm64 binary
  (`a26980a2…`) passes `codesign -v`. `bin/promote-local-candidate
  --verify-only` passed for that identity and refused a copy with one byte
  appended.
- **Native runtime and plugin:** the darwin/arm64 binary created and
  upgraded a synthetic signet to format 2, then ran `mandalore serve` over
  HTTP/1.1. `/healthz` answered 200, MCP `tools/list` listed all 12
  `memory_*` tools, and `memory_remember` then `memory_recall` saved and
  found a record. The plugin is unchanged at 2.2.0, so no plugin install
  was run.
- **Upgrade, rollback and re-upgrade:** 2.2.0 → 2.2.1 → 2.2.0 → 2.2.1,
  - through the launcher, from the published 2.2.0 to the candidate, then
    `--retained 6cda9389…` and `--retained a1a348ee…`, each reporting the
    expected version and Go toolchain;
  - as a bare binary, with the atomic swap, each step reporting the expected
    version.

  A fresh install into an empty prefix gave 2.2.1 at `95bbf17`, and a
  launcher without a Mandalore ownership receipt was refused and left
  untouched.

[Publication](https://github.com/acoz-labs/mandalore/issues/253#issuecomment-6798127935)
([release record](https://github.com/acoz-labs/mandalore/issues/253#issuecomment-6798142271))
was by the independent maintainer through `bin/promote-local-candidate`,
after the release gate passed against the acceptance receipt. It published
release 441779194 with seven assets and returned `publication-verified`.

- **Same bytes:** `bin/release-publication verify` passes for this identity,
  with seven assets whose digests equal the publisher's. All seven,
  downloaded fresh, are byte-identical to the accepted candidate,
  `SHA256SUMS` passes, and `manifest.json` hashes to `a1a348ee…`. The
  darwin/arm64 binary (`a26980a2…`) reports 2.2.1 at `95bbf17` with Go
  1.26.11 and passes `codesign -v`. `gh release verify v2.2.1` passes, and
  `gh release verify-asset` passes for `manifest.json` and that binary.
- **Vulnerability scan at the tag:** `govulncheck` v1.9.0 at `95bbf17`
  reports no reachable vulnerability (GO-2026-5932, unreached, only), and
  binary mode is clean on all four published binaries. The published 2.2.0
  binary still reports GO-2026-6859.
- **Public installation:** with a temporary `HOME`, from 2.2.0 in the default
  prefix, the published `sh install.sh 2.2.1` gave 2.2.1 at `95bbf17` with
  2.2.0 retained, and the installed runtime is byte-identical to the
  published binary. Rollback with `--retained 6cda9389…` and forward again
  with `--retained a1a348ee…` both applied.
- **Immutable:** v2.2.1 is immutable and not a draft or prerelease, with its
  tag at `95bbf17`. v2.2.0 is unchanged.

Out of scope: darwin/amd64, linux/amd64 and linux/arm64 weren't run natively
(cross-builds aren't native acceptance), native OAuth installations, a Claude
Code session driven by a model, and the live `launchctl kickstart -k` step of
the bare-binary upgrade. GO-2026-6859's race itself wasn't reproduced; the
criterion is the toolchain and the `govulncheck` result. No container image is
published. A release is not proof that any machine updated: no live server
was upgraded, and a server is protected only once the owner upgrades it to
2.2.1.
