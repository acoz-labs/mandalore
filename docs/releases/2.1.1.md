# Mandalore 2.1.1

[Release 2.1.1](https://github.com/acoz-labs/mandalore/releases/tag/v2.1.1)
makes the Claude plugin send Claude Code's session ID, so within one session
the prompt hook injects each record once, and again only after the record is
revised. The server is 2.1.0's: no server code changed.

**Servers must be on 2.1.0 or later before plugins update.** A 2.0.x server
refuses the plugin's new input, and every prompt then goes without memory (see
[The plugin](#the-plugin)). Installed plugins track the marketplace on `main`
([#229](https://github.com/acoz-labs/mandalore/issues/229)), so plugins update
when this change merges, before 2.1.1 is published.

2.1.1 changes no OAuth state version, no signet format and no configuration,
and adds no public HTTP or OAuth path.

container image: build from packaging/server; published image to follow.
([#188](https://github.com/acoz-labs/mandalore/issues/188); see
[Docker](../server.md#docker).)

## What changed

- **Once per session in Claude Code**
  ([#228](https://github.com/acoz-labs/mandalore/issues/228)). The plugin's
  `UserPromptSubmit` hook now sends `"session": "${session_id}"` to
  `memory_context`. Claude Code 2.1.310 substitutes its session ID there, the
  same across `--resume`, and 2.1.0's server de-duplicates on it
  ([Session](../server.md#tools)): a record revision injected earlier in the
  session is left out, a revised record is injected again, and the scopes are
  listed once. The server keeps this in memory, so a restart, or 12 hours
  idle, starts the session afresh.

On the synthetic evaluation set's scripted 20-turn session, the hook injects
353 bytes per prompt on average with the session, against 572 without (2.1.0's
plugin), 38% less; `TestContextSessionBytes` measures it. Native checks with
Claude Code 2.1.310 against 2.1.0 and 2.0.3 servers are in
[the evidence](../evidence/2.1/claude-session.md).

## Upgrading

### The server

A server on 2.1.0 needs nothing: 2.1.1's server behaves the same. From 2.0.x,
upgrade to 2.1.0 or 2.1.1 as
[2.1.0's notes](2.1.0.md#upgrading-a-running-launchd-server) describe, using
2.1.1 in place of 2.1.0, before the plugin updates.

### The plugin

The 2.1.1 plugin changes its hook input, version and README. Installations
pick it up when this change merges to `main`, and `claude plugin update
mandalore` fetches it at once.

Against a server older than 2.1.0, `memory_context` answers every prompt with
`input.invalid`, because 2.0.x refuses input fields it doesn't know. The hook
fails open: the prompt goes through without memory, under a non-blocking
"UserPromptSubmit hook error" line. The other tools are unaffected. Upgrading
the server ends it; nothing on the client needs to change.

## Recovery

Previous artifact: [2.1.0](2.1.0.md). Rolling the server back to 2.1.0 changes
nothing. Rolling it back to 2.0.3 while plugins are on 2.1.1 loses hook
context on every prompt, as above. If a server has to stay on 2.0.x, a plugin
version on `main` without the `session` input, with a higher version than
2.1.1 so installations update to it, restores the hook.
