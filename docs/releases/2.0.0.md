# Mandalore 2.0.0

[Release 2.0.0](https://github.com/acoz-labs/mandalore/releases/tag/v2.0.0)
replaces the 1.x model, where every device synchronized its own Git clone, with
one server per signet ([#168](https://github.com/acoz-labs/mandalore/issues/168)).
`mandalore serve` is the signet's only writer. Agents connect to it over MCP
with OAuth and the owner's passkey approval, and the server records which client
wrote each revision and pushes the signet to its remote as a backup. It is a
clean break from 1.x: once a signet is cut over, no 1.x client writes to it
again. See the [server](../server.md) and the [cutover](../migration-2.0.md).

## What changed

- **Server** ([#167](https://github.com/acoz-labs/mandalore/issues/167)):
  `mandalore serve` holds one lock per signet, serves MCP over Streamable HTTP
  and records per-client authorship.
- **OAuth** ([#161](https://github.com/acoz-labs/mandalore/issues/161),
  [#177](https://github.com/acoz-labs/mandalore/issues/177)): a built-in
  OAuth 2.1 authorization server with the owner's passkey approval, read-only and
  read-write client scopes, revocation and refresh-token reuse detection.
- **Foundlings** ([#162](https://github.com/acoz-labs/mandalore/issues/162)):
  canon refresh, legacy references and promotion run on the server.
- **Claude plugin** ([#163](https://github.com/acoz-labs/mandalore/issues/163)):
  one plugin from the repository's marketplace, with recall on every prompt
  through the `memory_context` hook. It fails open when the server is down.
- **Cutover** ([#164](https://github.com/acoz-labs/mandalore/issues/164)):
  `mandalore server migrate preflight|init|retire|verify`.
- **Packaging** ([#165](https://github.com/acoz-labs/mandalore/issues/165)):
  a launchd service, `packaging/server/Dockerfile`, and guides for a
  [work laptop](../deploy/local.md) and a
  [home server behind Cloudflare Tunnel](../deploy/cloudflare-tunnel.md).

## Breaking changes

- The Codex, Pi and Hermes plugins and every native-connection surface are
  removed ([#163](https://github.com/acoz-labs/mandalore/issues/163)).
- The CLI operation catalog goes from 68 in 1.6.1 to 41. #163 removed 20 of them
  (`connection_*`, `claude_code_connection_*`, `pi_connection_*`,
  `hermes_connection_*` and `*_package_inspect`). The 1.x sync and session
  operations (`memory_sync`, `memory_sync_status`, `memory_remember_and_sync`,
  `memory_journal_append_and_sync`, `memory_session_catalog`) and the CLI's
  `memory_context` and `foundling_refresh` moved to the server.
- The release manifest drops the `codex-plugin` asset and the `plugin_sha256`
  field, so a 1.x binary can't install 2.0. Use the 2.0 bootstrap below.

## Installing 2.0

Bootstrap with the 2.0 release's own script. It verifies the platform binary
against `SHA256SUMS`, then runs that binary's installer:

```sh
curl -fsSLO https://github.com/acoz-labs/mandalore/releases/download/v2.0.0/install.sh
sh install.sh 2.0.0
```

Review `install.sh` before running it. In a prefix that holds a 1.x install (both
default to `~/.local`), 2.0 updates it in place and keeps the 1.x runtime as the
previous one. Then configure the [server](../server.md#configuration) and install
the Claude plugin from the marketplace. Publication does not update any existing
installation by itself.

## Upgrade from 1.x

Follow [the cutover runbook](../migration-2.0.md#runbook). A format 1 signet is
upgraded first, with the 1.6.1 binary: stop every 1.x writer, run
`signet_upgrade_preview`, then `signet_upgrade_apply` with
`stopped_writers: true`, and sync. Then preflight every device, stop all 1.x
sessions, sync a final time, preflight again, retire each device, run `init` and
`verify` on the server, start it, and install the 2.0 plugin.

## A new signet

`signet create` still writes format 1, and the server needs format 2. A new
signet goes through the same upgrade with the 2.0 binary before `init`; see
[A new signet](../server.md#a-new-signet).

## Recovery

Previous artifact: [1.6.1](1.6.1.md) (manifest
`6b9f5107b0d7dfd8bf8d0323b38e52276b9d0ec702ffee2b1b983af0e5824f1d`). Roll the
CLI back with the 2.0 launcher's retained rollback:
`mandalore release install --retained 6b9f5107b0d7dfd8bf8d0323b38e52276b9d0ec702ffee2b1b983af0e5824f1d --prefix PREFIX`.
1.6.1 can't read a 2.0 install, so return to 2.0 with `sh install.sh 2.0.0`.
Where no 1.6.1 runtime is retained, as after a fresh 2.0 install, move both
`PREFIX/lib/mandalore` and `PREFIX/bin/mandalore` aside before installing
1.6.1, and put both back to undo ([the CLI install](../migration-2.0.md#the-cli-install)).

Rolling the CLI back doesn't roll a signet back. Before the first 2.0 write, one
clone can be un-retired and 1.x restarted. After it, 1.x must never write again
([Rollback](../migration-2.0.md#rollback)).

[Acceptance observations](ACCEPTANCE_EVIDENCE_LINK) used the actual release
binaries with a synthetic acceptance signet behind a throwaway tunnel hostname
(design section 9). The owner approved OAuth on a phone, and a memory saved from
the claude.ai client was durable and attributed to it. Claude Code on a
different Mac received it in the `memory_context` hook output on its next
prompt. A read-only client was refused a write, a revoked client got 401, a
reused refresh token revoked its family, Claude Code still answered with the
server stopped, and the push reached the remote. Install, update in place over
1.6.1 and retained rollback to 1.6.1 were exercised in synthetic prefixes.

darwin/amd64 and linux/amd64 received build and integrity verification only;
no native host was available for them. [Publication evidence](PUBLICATION_EVIDENCE_LINK)
covers same-byte downloads, immutable release metadata and public installation.
The cutover of a production signet is the operator's separate step, outside
this release.
