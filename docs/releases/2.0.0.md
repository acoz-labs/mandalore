# Mandalore 2.0.0

[Release 2.0.0](https://github.com/acoz-labs/mandalore/releases/tag/v2.0.0)
replaces the 1.x model, where every device synchronized its own Git clone, with
one server per signet ([#168](https://github.com/acoz-labs/mandalore/issues/168)).
`mandalore serve` is the signet's only writer. Agents connect to it over MCP
with OAuth and the owner's passkey approval, and the server records which client
wrote each revision and pushes the signet to its remote as a backup. It is a
clean break from 1.x: once a signet is cut over, no 1.x client writes to it
again. See the [server](../server.md) and the [cutover](../migration-2.0.md).

## What changed

- **Server** ([#167](https://github.com/acoz-labs/mandalore/issues/167)):
  `mandalore serve` holds one lock per signet, serves MCP over Streamable HTTP
  and records per-client authorship.
- **OAuth** ([#161](https://github.com/acoz-labs/mandalore/issues/161),
  [#177](https://github.com/acoz-labs/mandalore/issues/177)): a built-in
  OAuth 2.1 authorization server with the owner's passkey approval, read-only and
  read-write client scopes, revocation and refresh-token reuse detection.
- **Foundlings** ([#162](https://github.com/acoz-labs/mandalore/issues/162)):
  canon refresh, legacy references and promotion run on the server.
- **Claude plugin** ([#163](https://github.com/acoz-labs/mandalore/issues/163)):
  one plugin from the repository's marketplace, with recall on every prompt
  through the `memory_context` hook. It fails open when the server is down.
- **Cutover** ([#164](https://github.com/acoz-labs/mandalore/issues/164)):
  `mandalore server migrate preflight|init|retire|verify`.
- **Packaging** ([#165](https://github.com/acoz-labs/mandalore/issues/165)):
  a launchd service, `packaging/server/Dockerfile`, and guides for a
  [work laptop](../deploy/local.md) and a
  [home server behind Cloudflare Tunnel](../deploy/cloudflare-tunnel.md).

## Breaking changes

- The Codex, Pi and Hermes plugins and every native-connection surface are
  removed ([#163](https://github.com/acoz-labs/mandalore/issues/163)).
- The CLI operation catalog goes from 68 in 1.6.1 to 41. #163 removed 20 of them
  (`connection_*`, `claude_code_connection_*`, `pi_connection_*`,
  `hermes_connection_*` and `*_package_inspect`). The 1.x sync and session
  operations (`memory_sync`, `memory_sync_status`, `memory_remember_and_sync`,
  `memory_journal_append_and_sync`, `memory_session_catalog`) and the CLI's
  `memory_context` and `foundling_refresh` moved to the server.
- The release manifest drops the `codex-plugin` asset and the `plugin_sha256`
  field, so a 1.x binary can't install 2.0. Use the 2.0 bootstrap below.

## Installing 2.0

Bootstrap with the 2.0 release's own script. It verifies the platform binary
against `SHA256SUMS`, then runs that binary's installer:

```sh
curl -fsSLO https://github.com/acoz-labs/mandalore/releases/download/v2.0.0/install.sh
sh install.sh 2.0.0
```

Review `install.sh` before running it. In a prefix that holds a 1.x install (both
default to `~/.local`), 2.0 updates it in place and keeps the 1.x runtime as the
previous one. Then configure the [server](../server.md#configuration) and install
the Claude plugin from the marketplace. Publication does not update any existing
installation by itself.

## Upgrade from 1.x

Follow [the cutover runbook](../migration-2.0.md#runbook). A format 1 signet is
upgraded first, with the 1.6.1 binary: stop every 1.x writer, run
`signet_upgrade_preview`, then `signet_upgrade_apply` with
`stopped_writers: true`, and sync. Then preflight every device, stop all 1.x
sessions, sync a final time, preflight again, retire each device, run `init` and
`verify` on the server, start it, and install the 2.0 plugin.

## A new signet

`signet create` still writes format 1, and the server needs format 2. A new
signet goes through the same upgrade with the 2.0 binary before `init`; see
[A new signet](../server.md#a-new-signet).

## Recovery

Previous artifact: [1.6.1](1.6.1.md) (manifest
`6b9f5107b0d7dfd8bf8d0323b38e52276b9d0ec702ffee2b1b983af0e5824f1d`). Roll the
CLI back with the 2.0 launcher's retained rollback:
`mandalore release install --retained 6b9f5107b0d7dfd8bf8d0323b38e52276b9d0ec702ffee2b1b983af0e5824f1d --prefix PREFIX`.
1.6.1 can't read a 2.0 install, so return to 2.0 with `sh install.sh 2.0.0`.
Where no 1.6.1 runtime is retained, as after a fresh 2.0 install, move both
`PREFIX/lib/mandalore` and `PREFIX/bin/mandalore` aside before installing
1.6.1, and put both back to undo ([the CLI install](../migration-2.0.md#the-cli-install)).

Rolling the CLI back doesn't roll a signet back. Before the first 2.0 write, one
clone can be un-retired and 1.x restarted. After it, 1.x must never write again
([Rollback](../migration-2.0.md#rollback)).

## Evidence and scope

[Acceptance](https://github.com/acoz-labs/mandalore/issues/166#issuecomment-6398321115)
([receipt](https://github.com/acoz-labs/mandalore/issues/166#issuecomment-6398363011))
was run by the independent maintainer against the retained candidate
`mandalore:08be339d78c269e7de57e64f90c915dd1ab0af5c:sha256:f9ffce7c637baa4623a1106163fceba1427a6102862204a327de8b8805107d44`,
on synthetic signets in temporary directories only:

- **Retained distribution:** `bin/build-artifacts` from a clean clone at
  `08be339` gave the seven files, and `bin/promote-local-candidate --verify-only`
  passed for that identity.
- **Native runtime:** darwin/arm64 ran every step; linux/arm64, in a Linux VM,
  served a synthetic signet with a durable write and the server head equal to the
  remote head.
- **claude.ai on a phone** (design section 9, acceptance 1), over a real
  Cloudflare Tunnel on a throwaway hostname: the owner enrolled a real passkey
  and approved the claude.ai connector read-write. A `memory_remember` from the
  phone chat was durable, its revision was attributed to the claude.ai client's
  own device with harness `claude.ai`, and the backup was pushed
  ([connector check](https://github.com/acoz-labs/mandalore/issues/161#issuecomment-6398324913)).
- **Claude Code on a second Mac** (acceptance 2), with a read-only grant: a fresh
  session that named no tool received that fact in the `memory_context` hook
  context, made no tool calls and answered from it. It authorized headlessly,
  with `claude mcp login --no-browser` and the loopback callback pasted back.
- **Supporting checks** (acceptance 3): a read-only token was refused a write, a
  revoked client got 401 on loopback, a reused refresh token revoked its family,
  and Claude Code still answered with the server stopped, stalled or unapproved.
  Over the tunnel, after the claude.ai client was revoked, its tool calls all
  failed and returned no data. The server keeps no request log, so the response
  was reproduced afterwards on the same code paths through the tunnel: MCP
  returned 401, and a refresh returned `invalid_client`.
- **Cutover:** a synthetic two-device format 1 signet went through upgrade,
  preflight, retire with the real Claude Code, Codex and Pi disables, `init` and
  `verify`.
- **Installation and recovery**, in isolated prefixes with the real 1.6.1
  binary: a fresh 2.0 install, 2.0 over 1.6.1 in the same prefix, retained
  rollback to 1.6.1 and forward again, the documented refusal by the 1.6.1
  binary, the `install.sh` checksum check, and refusals of tampered retained
  files, of an incompatible manifest and of unknown ownership.

Out of scope: darwin/amd64 and linux/amd64 had no native host (cross-builds
aren't native acceptance), and Hermes was exercised with test fakes only. The
production cutover, and the repeat of acceptance 1 and 2 on the production
signet, are the operator's, after publication.

The release audit of 1.6.1..`08be339` fails only on #167's merge `982e4d7`
([#169](https://github.com/acoz-labs/mandalore/pull/169)), whose validation
receipt wasn't published before the merge; that gap is
[recorded on #167](https://github.com/acoz-labs/mandalore/issues/167#issuecomment-6392137308).

[Publication](https://github.com/acoz-labs/mandalore/issues/166#issuecomment-6398446209)
([receipt](https://github.com/acoz-labs/mandalore/issues/166#issuecomment-6398453981))
was by the independent maintainer through `bin/promote-local-candidate` after
the release gate passed:

- **Same bytes:** all seven assets, downloaded publicly without authentication,
  have the accepted candidate's SHA-256 digests, `shasum -c SHA256SUMS` passes,
  and `manifest.json` hashes to `f9ffce7c…`. GitHub's asset digests match and
  `gh release verify v2.0.0` passes, with the tag resolving to `08be339`.
- **Immutable:** v2.0.0 is immutable and marked Latest. v1.6.1's release
  metadata, assets and tag are unchanged.
- **Public installation** on darwin/arm64, from the published bytes in isolated
  homes: a fresh `sh install.sh 2.0.0`, the in-place update over a public 1.6.1
  install, retained rollback to 1.6.1 and forward again, both with `install.sh`
  and with the retained 2.0 runtime, and the documented refusal of 1.6.1's
  `install.sh` over 2.0.

`bin/promote-local-candidate` and `bin/release-publication verify` both exited 1
after the verified publish, on a stale check that expects the eight 1.x assets
([#193](https://github.com/acoz-labs/mandalore/issues/193)). The published state
was inspected and nothing was retried; `distribution.VerifyPublication` at
`08be339` returns `publication-verified` for this identity with seven assets.
amd64 installation wasn't run natively.

## Known issues

- [#191](https://github.com/acoz-labs/mandalore/issues/191): the 401 lacks
  `error="invalid_token"`, and a revoked client's refresh gets `invalid_client`
  instead of `invalid_grant`.
- [#192](https://github.com/acoz-labs/mandalore/issues/192): there is no
  revocation endpoint, so a client logout leaves its server tokens live until
  revoked with `server clients revoke`.
- [#193](https://github.com/acoz-labs/mandalore/issues/193): the release
  publication tools expect eight assets and exit 1 after a 2.0 publish.
- [#194](https://github.com/acoz-labs/mandalore/issues/194): the install preview
  shows signet schema `read 1, write 1`; 2.0 reads and writes 1 and 2.
- [#188](https://github.com/acoz-labs/mandalore/issues/188): no container image
  is published yet.
