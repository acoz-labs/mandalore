# Mandalore 1.6.0

[Release 1.6.0](https://github.com/acoz-labs/mandalore/releases/tag/v1.6.0)
adds the [Hermes integration](../hermes.md): owned connection installation and
recovery, native memory tools and skills, foreground context refresh, and
shared-engine delivery after semantic saves. Hermes keeps its own memory,
learned procedures, authentication and model selection. Mandalore stores portable
confirmed knowledge and useful semantic outcomes without mirroring native files
or extracting transcripts.

## Evidence and scope

[Native scenario observations](https://github.com/acoz-labs/mandalore/issues/153#issuecomment-5988496531)
and [configured acceptance](https://github.com/acoz-labs/mandalore/issues/153#issuecomment-5988532664)
cover actual Hermes 0.21.5 CLI and isolated persistent-service entry points on
macOS arm64, and actual Linux arm64 CLI/protocol save and recall. The amd64
payloads received build and integrity verification; native amd64 execution was
not available. This baseline does not claim every Hermes version is accepted.

The native scenarios exercised an offline Hermes save, delivery of the same head
at a later foreground boundary, Pi 0.85.1 correction of the same record, Hermes
recall of that correction, and propagation of a withdrawal. A local scripted
provider made those native tool sequences deterministic. Separate real-model
Astra observations demonstrated portable preference learning, an explicit
no-save/no-journal request, and refusal to restore withdrawn knowledge from stale
native notes. Those observations do not guarantee every future model decision.

Read-only enforcement, changed runtime/binding refusal, incompatible connection
schema rejection, unknown ownership refusal, retained-generation repair and
fresh-process native disable were exercised. Disabling does not remove already
loaded context. See the [lifecycle and timeout boundaries](../hermes.md#native-lifecycle-mapping)
before interpreting a receipt or a reconnect as a fresh session.

## Upgrade and recovery

Use an explicit release installation preview, then separately plan the Hermes
connection for the selected profile and signet binding. Stop affected native
sessions/services before activation and restart them afterward. Preserve the
previous runtime and owned connection generation. Existing read-only connections
are not silently upgraded to writable or synchronized connections.

Public installation proof covers fresh installation, update from 1.5.0, retained
rollback to 1.5.0, restoration to 1.6.0 and refusal to replace an unknown launcher.
A binary rollback does not authorize or reverse a signet schema migration. This
release requires no production signet migration. Operator-specific upgrades and
private signet checks are separate from publication and retain private receipts.
