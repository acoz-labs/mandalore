# Mandalore 1.4.0

Published 2026-09-27. Mandalore 1.4.0 adds canon foundlings and named signet launching.

## What changed

- **Legacy and canon foundlings.** Existing foundlings remain pinned historical references. A canon foundling tracks a branch of another Mandalore signet. Enabled sessions attempt a bounded refresh at startup and resume, then consult that session's immutable snapshot. References are directional and read-only; ordinary recall respects withdrawals and unresolved conflicts. Explicit promotion retains source provenance.
- **Named launch environments.** `mandalore launch work` starts the locally configured default harness and signet. `--agent codex`, `--agent pi`, or `--agent claude-code` selects another configured profile for that invocation. Preview inspects the connection; the launcher preserves arguments, working directory, terminal and native exit behavior. Optional shell shortcuts remain local shell configuration.

See [foundlings](../foundlings.md), [launching](../launch.md) and [setup](../setup.md).

## Upgrade and recovery

Update the CLI, then explicitly update each owned native connection with active sessions stopped. Start a fresh native session. Runtime installation does not migrate a signet, register a reference, configure named environments or copy authentication/history.

Canon uses foundling registration version 2. Older clients refuse a signet containing this metadata; removing the active reference does not erase its registration history. Binary rollback therefore does not reverse canon adoption. Keep an appropriate recovery copy before adopting new portable metadata. Legacy-only registrations retain older-reader compatibility.

A selected signet and native profile control memory routing, not operating-system access. Project instructions and native memory remain native features. Refresh cannot revoke content already loaded into an agent, and a successful fetch does not prove a source claim true.

## Verification scope

Acceptance evidence and public release verification are linked from issues [#142](https://github.com/acoz-labs/mandalore/issues/142) and [#143](https://github.com/acoz-labs/mandalore/issues/143). Native model acceptance ran on macOS ARM64 for all three harnesses. Linux ARM64 exercised runtime installation/recovery and Pi activation/context. AMD64 assets were cross-built and verified; native AMD64 and Linux model journeys were not exercised.

Supported native contracts remain Codex 0.155.1, Claude Code 2.1.278 and Pi 0.85.1. The setup prompt itself has no newly expanded acceptance claim in this release.
