# Mandalore 1.0.0

Published September 15, 2026:
[v1.0.0](https://github.com/acoz-labs/mandalore/releases/tag/v1.0.0).

The initial release is Codex-first: structured scoped memory, semantic journals,
provenance, explicit supersession, local-first Git synchronization, foundling
references, CLI/MCP, guided setup and The Armorer. It does not supply an assistant
identity, credential/capability framework or native thread portability.

## Installation and recovery

The macOS ARM64 public executable was run and matched the declared source/plugin
identity. Updating a disposable installation from the prior Mandalore candidate
to the public release passed, as did exact-plan replay, retained rollback and
roll-forward driven by the older executable. Both candidates have version 1.0.0;
the test distinguishes their source and manifest hashes, not version labels.
This is candidate-to-release updating, not a claim of an earlier public release.

The freshly downloaded binary also passed the native CLI/MCP probe: scoped
correction/history, no-write hash checks, local Git synchronization and clone
recall, a fresh offline installation from the downloaded assets, and synthetic
legacy conversion with original files preserved. Its exact installed version
matched the public executable. The existing owner-acceptance fixture stayed
unchanged. This does not replace the public-bootstrap journey below.
The [native probe receipt](1.0.0/native-cli-mcp.json) is unchanged output from the
previously reviewed model-free collector, now supplied with the public bytes.

One request was refused while staging; the old launcher remained unchanged and
the same reviewed plan completed on retry. Later bootstrap attempts exhausted
the machine's anonymous GitHub API quota and correctly refused without creating
the destination. After the quota reset, the real published `install.sh 1.0.0`
completed a clean installation into a disposable prefix on macOS ARM64. The
installed executable matched SHA-256
`bcc1b7fdf9e72ccb2bbd734d798c16f3aa5b96de757846711a4e5afe6eb00f93`,
its complete version result matched the downloaded public executable, and no
pending installation receipt remained. Native connections were left unchanged.
This verifies the public-bootstrap CLI installation journey on that platform;
it does not extend native conversation acceptance to other platforms.

Public release operations intentionally do not borrow CLI credentials. A shared
anonymous quota can be exhausted by repeated verification and installation.
Wait for the provider's reset rather than repeatedly retrying. A manual offline
alternative is to download all eight assets from this version's official release
into a new directory, verify `SHA256SUMS`, and use the verified platform binary's
`release install --candidate /absolute/download-directory`. This verifies local
payload integrity but is labeled local-candidate trust, not live published-release
inspection. The normal public bootstrap additionally requires curl 8.4+ and a
SHA-256 tool. Connections, signets, credentials and shell configuration are not
automatically changed by CLI installation.

## Supported and deferred

CLI/MCP binaries were actually exercised on macOS ARM64/AMD64 and Linux
ARM64/AMD64 before publication; public downloads match those accepted bytes.
Native Codex conversations were verified on macOS ARM64, not every CLI platform.
Pi and Claude Code integrations remain deferred. Lexical retrieval is bounded,
not infallible; synchronization receipts distinguish local durability, remote
delivery and semantic conflicts. Foundlings remain unreviewed source evidence,
not automatic authority or bulk migration. No real personal memory was migrated.
