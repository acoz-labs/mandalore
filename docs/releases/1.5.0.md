# Mandalore 1.5.0

Published 2026-09-30. [Release assets](https://github.com/acoz-labs/mandalore/releases/tag/v1.5.0).

## Native agent upgrades

Compatible Claude Code, Codex and Pi upgrades no longer require a Mandalore
release matching their exact version. Mandalore checks the native interfaces
needed by the requested operation. Tested versions are evidence baselines, not
an allowlist or a promise that every future upstream change will work.

Existing named launch entries follow verified same-install updater locations
when versioned executables are replaced or removed. New connections retain an
explicit stable launcher. The signet, profile, access mode, session transport
and immutable receipt remain pinned. Foreign or dangling updater targets and
missing required capabilities are refused. Installer-only flags do not block
launching an intact connection.

See [launching](../launch.md), [setup](../setup.md) and
[the implementation](https://github.com/acoz-labs/mandalore/pull/150).

## Upgrade and recovery

Update the CLI using the supported release plan/apply workflow. Updating the CLI
and updating a native plugin are separate operations. Before replacing an owned
plugin, exit all sessions using that profile, apply its reviewed connection plan,
and start a fresh native session. Native hook trust remains a native decision.
Updating a plugin generation may require updating its named launch configuration;
routine compatible native-agent upgrades do not.

No signet migration, credential copying or history migration is required for this
change. The immutable 1.4.0 release and retained runtimes remain available for CLI
recovery. CLI rollback does not roll back an independently updated native plugin
or reverse previously adopted signet metadata.

## Verification and scope

Independent [acceptance](https://github.com/acoz-labs/mandalore/issues/149#issuecomment-5919788707)
passed the configured checks at the exact merged source. On macOS ARM64, actual
native sessions verified hooks, signet selection, recall, semantic saves and
bounded automatic delivery after these upgrades:

- Claude Code 2.1.282 to 2.1.286.
- Codex 0.155.1 to 0.159.2.
- Pi 0.85.1 to 0.99.2.

Old fixture executables were removed while bindings, named entries and receipts
stayed unchanged. Genuine 1.4.0-created Codex/Pi receipts also launched through
the new CLI. Linux ARM64 exercised runtime installation, update, rollback and
restore, plus Pi registration, stable-launcher upgrade and policy-bound context.
Native AMD64 and Linux model inference were not exercised. The setup prompt has
no expanded acceptance claim. Failed fixture attempts and native approval-policy
refusals are retained in the issue evidence, distinct from successful runs.

This release publishes the native CLI/plugin distribution. The separate Razor
Crest service in [#146](https://github.com/acoz-labs/mandalore/issues/146) is not
accepted or deployed by this native release. Subsequent service checks and the
private installation are recorded in the [Razor Crest follow-up](1.5.0-razor-crest.md);
its remaining authentication-renewal criterion is explicit.
